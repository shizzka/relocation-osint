# Relocation OSINT

Инструмент для сравнительного исследования вариантов переезда с источниками.
Единица анализа — **страна / город**. Конвейер:
`01_fetch.py` → `02_judge.py` → `03_excel.py`.

## Запуск

```bash
cd relocation-osint
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python 01_fetch.py --plan --country 'COUNTRY_NAME'
.venv/bin/python 01_fetch.py --country 'COUNTRY_NAME' --city 'CITY_NAME'
.venv/bin/python 02_judge.py --country 'COUNTRY_NAME' --city 'CITY_NAME'
.venv/bin/python 03_excel.py
```

Создайте локальные `destinations.json` и `source_policy.json` из шаблонов
`destinations.example.json` и `source_policy.example.json`, затем заполните их
своим shortlist и проверенными доменами. При необходимости создайте локальный
`geography_aliases.json` по `geography_aliases.example.json`. Эти файлы исключены
из Git.
Скопируйте `.env.example` в `.env` и задайте профиль и API-провайдеры;
`.env` также исключён из Git.

Без фильтров сбор охватывает весь `destinations.json`: это много запросов.
Сначала запускайте одно направление из своего локального списка.
Свой список можно передать через `--destinations path.json`.
`--plan` ничего не отправляет в API. `--refresh` обновляет evidence и отчёты.

## Модели и аккаунты

Ключи читаются из файла, заданного `RELOCATION_PROVIDERS_FILE`; не храните их
в Git. Локальный `.env` и переменные процесса переопределяют настройки.
Имена параметров приведены в `.env.example`; персональный профиль задаётся
только в `.env`.

- Исследователи: `gpt-oss:120b`, `nemotron-3-super`, `gemini-3.5-flash`.
- GPT-OSS и Nemotron используют настроенные аккаунты OLLAMA, OLLAMA2 …
  OLLAMA9 по кругу, без дублирования одинаковых ключей.
- Gemini использует собственный API; при исчерпании аккаунтов GEMINI/2/3
  переходит на `gemma4:31b` через аккаунты Ollama.
- После scout-аккаунтов Ollama доступен OpenRouter fallback только на бесплатную
  модель `nvidia/nemotron-3-super-120b-a12b:free`. Он используется для генерации,
  не для поиска и не для DeepSeek-судьи. Бесплатный alias и фактическая модель
  сохраняются в provenance; платный вариант блокируется проверкой суффикса `:free`.
- При HTTP 429 на всех Ollama-аккаунтах runner сохраняет checkpoint и повторяет
  обработку через 15/30/60 минут, затем раз в час. Groq в этом проекте не
  используется; общие Groq-ключи могут применяться другими проектами.
- Без Gemini-ключа третьим исследователем автоматически становится Gemma.
- Судья: платный `deepseek-v4-pro` напрямую через DeepSeek,
  `thinking=enabled`, `reasoning_effort=high`. Другими семействами не заменяется.
  DEEPSEEK2/3 подключаются автоматически, если их ключи появятся в общем файле.
- Ошибки квот, авторизации и доступности модели переключают аккаунт;
  сетевые ошибки и 5xx сначала повторяются с задержкой.
- При общем HTTP 429 учитывается серверный `Retry-After`/rate-limit reset.
  Без reset-заголовка runner проверяет через 15, 30 и 60 минут, затем раз в
  час; после снятия лимита продолжает с сохранённого checkpoint.
  Базовый и максимальный интервалы задаются `RELOCATION_RATE_LIMIT_CHECK_SECONDS`
  и `RELOCATION_RATE_LIMIT_RETRY_SECONDS`.
- Полный runner фиксирует evidence на срок одного запуска, поэтому истечение
  обычного 24-часового TTL не откатывает долгий сбор к первой стране.
  Прогресс хранится атомарно в `data/out/fetch-state.json`; новый отдельный
  запуск после завершённого Excel снова применяет обычный TTL.

Список моделей проверен через API 30 сентября 2026. Kimi K3/K2.6, GLM 5.3
и Mistral Large 3 видны в каталоге, но генерация отвечает HTTP 402 на текущих
аккаунтах. Поэтому они не используются по умолчанию. API моделей динамичен:
переопределите `RELOCATION_MODELS` и `RELOCATION_JUDGE_MODEL`, если доступ изменится.
Текущий механизм намеренно сохраняет семейство модели при смене Ollama-аккаунта.
Он не импортирует JobHunter и не меняет его код или конфигурацию ролей.

Документация API: [Ollama search](https://docs.ollama.com/capabilities/web-search),
[DeepSeek thinking](https://api-docs.deepseek.com/guides/thinking_mode/).

## Данные и проверки

Country layer: легализация, налоги, крипта, визы, банки, экономика,
геополитические/правовые риски, долгосрочные перспективы.
City layer: аренда/стоимость жизни, климат, сервис, медицина, школы,
транспорт, пешеходность, природа, язык, дети, безопасность и культура.
Нумерация прежних 20 критериев сохранена. Национальный отчёт и вердикт
собираются один раз на страну и используются для всех её городов.

Поиск отделён от генерации. Для этого цикла в `.env` задано
`RELOCATION_SEARCH_PROVIDER=tavily`: веб-поиск идёт только через Tavily Search,
а генерация отчётов остаётся на Ollama. Режимы `balanced` (поровну Ollama
`web_search`/Tavily с fallback) и `ollama` доступны настройкой.
Для Tavily читаются `TAVILY_API_KEY`, `TAVILY2_API_KEY` … из общего файла
провайдеров; при ошибке ключи переключаются.
Остаток квоты проверяется через Tavily `GET /usage`, поисковые кредиты на это
не тратятся; учёт сверяется с фактическими `usage.credits` и сохраняется локально,
если серверный счётчик обновляется с задержкой. Если назначенный сервис временно ограничен, запрос уходит второму;
для ограничения частоты отказавшему сервису применяется пауза 15/30/60 минут.
`source_policy.json` применяется программно **до передачи источников модели**:
denylist имеет приоритет; неизвестные домены отклоняются; official=3,
dataset=2, media/community=1. Это оценка происхождения, не доказательство
истинности страницы. Расширяйте allowlist сайтами местных банков, школ,
больниц и транспорта после ручной проверки. Часть источников будет потеряна
при строгом первоначальном списке — соответствующие пробелы видны в отчёте.

Глобального ограничения `year` нет: действующая норма может быть старой.
Дата получения, дата публикации и дата действия хранятся отдельно.
Поисковые выдержки помечены `search_excerpt`; дата действия неизвестна,
если её не удалось установить. Поисковая выдача не заменяет чтение полной
действующей редакции закона. Содержание страниц считается недоверенным.

Проверки требуют точные страну/город, уникальные id, полноту набора,
целые оценки 0..10 либо явный `null`, непустые резюме и корректные ссылки
на источники соответствующего критерия. Неподтверждённая оценка отвергается.
Невалидный JSON или неполный ответ исправляются максимум трижды.
Если модель даёт оценку со ссылкой на чужой критерий, эта оценка программно
понижается до `null`, а исходный ID остаётся в `citation_validation_warnings`;
проверка не превращает её в ноль и не позволяет источнику подтверждать другой факт.
Запись JSON атомарна; повреждённые файлы не подменяются пустой базой.
Кэш зависит от evidence, промпта, профиля, критериев и модели.
Evidence по умолчанию живёт 24 часа; затем отчёты пересчитываются.

Судья получает **все** критерии и источники, а не только расхождения баллов.
Общий поиск явно отмечен `independent_retrieval=false`: три исследователя
не являются тремя независимыми подтверждениями. Уверенность — эвристика
происхождения и полноты, не вероятность правильности. При общем retrieval
она не выше `medium`; по критическим вопросам без официального источника
и при единственной фактической модели — `low`. ВНЖ, налоги и банки требуют
ручной проверки даже при наличии ссылок.

Новые результаты изолированы в `data/raw_v2/`, `data/evidence/`,
`data/out/judged_{country,city}_v2.json`, `data/out/master_v2.json`.
Исходные `data/raw/` и `data/out/master.json` сохранены.
Локальные raw-отчёты, evidence, shortlist и пользовательская рабочая память
в безопасный набор Git не включаются.

## Excel и аудит

```bash
.venv/bin/python audit.py
.venv/bin/python 03_excel.py --input data/out/master.json
```

Excel содержит листы «Анализ», «Подробный анализ», «Источники» с кликабельными
ссылками и полным финальным анализом. Балл — взвешенное среднее 0..10.
Веса редактируются во второй строке; отрицательные значения не допускаются.
Пропуск не равен нулю: пока у критерия с ненулевым весом нет оценки,
вместо итогового балла выводится «НЕДОСТАТОЧНО ДАННЫХ» и отдельно покрытие.
При весе 0 непроверенный критерий исключается из сравнения явно.
Старые country-отчёты подписаны «страна; города нет», уверенность не оценена,
потерянные привязки ссылок не восстанавливаются догадками.

`audit.py` проверяет старые локальные данные и пишет `data/out/audit.json`.
Это структурный аудит и проверка происхождения, не юридический фактчекинг.
Рабочая память и исходные находки — в `PROJECT_MEMORY.md`.
